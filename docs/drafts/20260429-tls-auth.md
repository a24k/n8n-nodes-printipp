# TLS and Authentication Support

**Date:** 2026-04-29  
**Status:** Draft

---

## Goal

Extend the `printIpp` credential to support HTTPS (IPPS) and HTTP Basic Authentication, covering the common CUPS deployment scenarios encountered by community node users.

---

## Credential Fields

Add three fields to `src/credentials/PrintIpp.credentials.ts`:

| Field | Type | Default | Display condition |
|-------|------|---------|-------------------|
| `protocol` | `options` (`http` / `https`) | `http` | Always |
| `password` | `string` (secret/password type) | `""` | Always |
| `skipCertValidation` | `boolean` | `false` | `protocol = https` only |

The `password` field uses n8n's `typeOptions: { password: true }` so n8n encrypts it at rest.

The `skipCertValidation` field uses `displayOptions.show: { protocol: ['https'] }` so it is visible only when `protocol` is `https` and hidden for `http`. This allows users with self-signed certificates to opt in to skipping validation while keeping the option invisible for plain HTTP connections.

The existing `username` field is unchanged — it remains the IPP `requesting-user-name` sent in every IPP operation.

---

## URL Construction

The printer URL is constructed at runtime as:

```
{protocol}://{host}:{port}/printers/{printerName}
```

When `password` is non-empty, Basic Auth credentials are embedded in the URL:

```
{protocol}://{username}:{password}@{host}:{port}/printers/{printerName}
```

The CUPS root endpoint (used by Test Connection) follows the same pattern without the printer path segment.

---

## `IppPrinterFactory` Signature Change

The factory type is extended to accept connection options:

```typescript
export interface IppConnectionOptions {
  rejectUnauthorized: boolean;
}

export type IppPrinterFactory = (
  url: string,
  options: IppConnectionOptions,
) => IppPrinterInstance;
```

`rejectUnauthorized` maps directly to the TLS option of the same name. When `skipCertValidation` is `true`, `rejectUnauthorized` is `false`; otherwise it is `true`.

The `defaultPrinterFactory` passes the options to the `ipp` package's `Printer(url, options)` constructor.

---

## Call Sites

All four call sites that construct a URL and invoke a factory are updated to read `protocol`, `password`, and `skipCertValidation` from the credential and pass them through:

- `fetchPrinterAttributes` — attribute discovery when a printer is selected
- `fetchCupsPrinters` — populates the Printer Name dropdown
- `executeIppJob` (inside `PrintIpp` constructor) — sends the print job
- `testCupsConnection` — handles the Test Connection button

---

## Error Handling

Existing `continueOnFail` and try/catch patterns are unchanged. The Test Connection handler (`testCupsConnection`) adds one new case: if the caught error message contains `certificate` or `CERT`, it returns `"Connection failed: certificate validation error"` to guide users toward enabling `Skip Certificate Validation`.

---

## Tests

`IppPrinterFactory` mock signatures are updated from `(url)` to `(url, options)`. No mock logic changes are needed — only the signature.

New unit test cases (in the existing test file):

| Scenario | Assertion |
|----------|-----------|
| `protocol=https`, no password | URL starts with `https://`, no `@` in URL |
| `protocol=https`, password set | URL contains `username:password@` |
| `skipCertValidation=true` | `options.rejectUnauthorized === false` passed to factory |
| `skipCertValidation=false` | `options.rejectUnauthorized === true` passed to factory |
| `protocol=http`, `skipCertValidation` irrelevant | `rejectUnauthorized === true` (safe default) |
